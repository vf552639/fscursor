# Серверные действия в десктопе: SSH Test и метрики

**Ветка:** `feature/stage2-desktop`. Найдено при живом прогоне 2026-08-05.

## Контекст

Кнопки на карточке сервера зовут HTTP-эндпоинты, которых на бэкенде нет (проверено по логу
живого прогона — **404**):

| Кнопка | Зовёт | Реальность |
|---|---|---|
| SSH Test | `POST /api/servers/{id}/test-ssh` (`api/servers.ts:180`) | роута нет |
| Refresh | `POST /api/servers/{id}/refresh-metrics` (`api/servers.ts:186`) | роута нет |

Это остаток переезда выполнения в десктоп (Stage 3–4): серверные роуты убрали, фронт остался на
старом API. Тот же класс, что 10 мёртвых доменных маршрутов из итога cleanup-спринта
(`2026-08-04-cleanup-debt-9-12.md`), но серверные в тот список не попали.

**Почему это не могло работать в принципе.** У сервера нет и не может быть SSH-пароля: он лежит
блобом, зашифрованным мастер-ключом, который сервер не видит. Значит SSH — только из десктопа.
`ssh_exec` для этого уже есть и принимает плейнтекст пароля; расшифровать блоб умеет
`vault_decrypt_blob` — но **во фронте он не вызывается ни разу**, то есть точки входа нет
(остаток долга Спринта 1 «часть Tauri-команд без точки входа в UI»).

## Фаза 1 — SSH Test через десктоп [ ]

Заменить HTTP-вызов на путь: `vault_decrypt_blob(userId, ssh_password_blob_id)` →
`ssh_exec(host, port, user, password, "<безобидная команда>")` → показать результат.

- Пароль живёт в памяти ровно до вызова: не в state, не в `variables` мутации (ловушка описана в
  `secretBlob.ts` — react-query держит `variables` даже после `reset()`).
- `HOST_KEY_UNKNOWN`: `ssh_exec` эмитит `ssh:host-key-prompt` и возвращает ошибку. Сегодня
  подписка на это событие живёт только в `DesktopWorkspace` (для provision) — на странице сервера
  её нет, поэтому первый в жизни коннект к хосту молча провалится. Нужна обработка и здесь:
  показать отпечаток, принять через `ssh_accept_host_key`, повторить.
- Сервер без `ssh_password_blob_id` (все записи до Спринта 4 такие) — кнопка объясняет, что
  пароль не задан, а не падает.

**Приёмка:** реальный сервер, реальный SSH, зелёный результат в UI. Проверять по факту
подключения, а не по «мутация отработала».

Критические файлы: `frontend/src/api/servers.ts`, `frontend/src/pages/ServerDetail.tsx`,
`frontend/src/lib/` (обёртка над decrypt+exec).

## Фаза 2 — Refresh метрик [ ]

**Требует новой работы в Rust: сборщика метрик нет вообще** (`grep uptime_seconds|cpu_usage` по
`desktop/src-tauri/src` — ни одного места записи). Колонки в БД есть и пустуют; в
`dashboardData.ts:6` это уже честно оговорено.

Сделать: Tauri-команда, которая по SSH снимает uptime / CPU / RAM / диск, и write-back результата
в метаданные сервера (путь `server_write_back` уже есть).

Открытый вопрос — формат снятия: `/proc` + `df` построчно или один скрипт. Решать при реализации,
опираясь на то, что вывод уходит в метаданные и не должен тащить лишнего.
