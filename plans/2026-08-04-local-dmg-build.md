# План: повторяемая локальная сборка macOS .dmg + запуск

**Дата:** 2026-08-04
**Связь с бизнесом:** без воспроизводимой сборки десктопа нельзя ни отдать бинарь на
тест, ни готовиться к релизу — а десктоп в нашей модели единственное место, где вообще
выполняются операции (см. принцип «desktop выполняет, web только смотрит»).

## Зачем

`tauri build` в проекте есть, но процесс не документирован и ни разу не запускался
(`src-tauri/target/release/bundle` пуст). Цель — **один повторяемый способ собрать `.dmg`
на этой машине и запустить его**. Подпись, нотаризация, CI и другие ОС — Stage 5.

## Исходное состояние (сверено по коду)

- `desktop/package.json` → `npm run build` = `tauri build`; `beforeBuildCommand` собирает фронт
  (`cd ../frontend && npm run build` = `tsc && vite build`).
- Иконки на месте (`icons/icon.icns`), bundle-таргеты заданы, тулчейн стоит
  (cargo/rustc 1.95, node 24.10, npm 11.6, rustup-таргет `aarch64-apple-darwin`).
- Release-сборки не было: в `src-tauri/target` только `debug`.
- Backend на :8100 живой (`/health` → 200).

## Острые углы, которые закрываем

1. `bundle.targets` = `["dmg", "nsis", "appimage"]` — на маке собираем только
   `--bundles app,dmg`, иначе шум и ошибки по Windows/Linux-таргетам. Именно
   `app,dmg`, а не один `dmg`: с одним `dmg` tauri после упаковки образа вычищает
   `bundle/macos/`, и `.app` для `--run` не остаётся.
2. Собранный `.app` смотрит на `SDMP_API_URL` (дефолт `http://localhost:8100/api`,
   `desktop/src-tauri/src/lib.rs:25`) — нужен поднятый backend. Документируем как предусловие.
3. Приложение неподписанное, но **локально собранный** `.app` не получает атрибут
   `com.apple.quarantine` (он ставится только при скачивании) → запускается без
   Gatekeeper-пляски. Дока фиксирует это, чтобы не путать со сценарием «скачал .dmg»
   из `docs/INSTALL.md`.
4. `bundle_dmg.sh` зовёт Finder через `osascript` ради раскладки иконок в окне DMG.
   Без разрешения Automation → Finder (агентский шелл, ssh, CI) это падает с
   `-1743`, а tauri показывает лишь `failed to bundle project`. Скрипт ловит это
   сам и повторяет сборку один раз с `CI=true` (tauri передаёт `--skip-jenkins`,
   косметика пропускается). Дока объясняет, как выдать доступ.

## Acceptance criteria

- [x] `./desktop/scripts/build-dmg.sh` одной командой собирает `.dmg` с нуля.
- [x] Preflight ловит отсутствие `cargo`/`rustc`/`node`/`npm`/rustup-таргета понятной
      ошибкой с командой установки, а не падением внутри `tauri build`.
- [x] Скрипт печатает пути к `.dmg` и `.app`.
- [x] `--run` открывает собранный `.app`, предварительно напомнив про backend на :8100.
- [x] `docs/BUILD.md` описывает предусловия, одну команду, путь артефакта, запуск и
      острый угол с backend; из `docs/INSTALL.md` есть ссылка.
- [x] Повторный прогон скрипта идемпотентен — без ручных шагов.

## Edge cases

- Нет `node_modules` в `desktop/` → скрипт сам делает `npm install` (нужен `@tauri-apps/cli`).
- Нет `node_modules` во `frontend/` → `beforeBuildCommand` упадёт на `tsc`; preflight
  проверяет и это.
- Не тот процессор (Intel-мак) → собираем только host-арку, universal — Stage 5 (YAGNI).
- Backend не поднят → пустой экран/сетевая ошибка в приложении; это не баг сборки,
  дока говорит об этом прямо.
- Zero-knowledge: сборка не трогает секреты; в логах скрипта плейнтекста нет.

## Фазы

### Фаза 1 — скрипт сборки `desktop/scripts/build-dmg.sh`  `[x]`

- Preflight (тулчейн + rustup-таргет + node_modules фронта), `npm install` при нужде,
  `npm run tauri build -- --bundles app,dmg`, печать путей, `--run` → `open` `.app`.
- Только host-арка `aarch64`.
- Файлы: `desktop/scripts/build-dmg.sh` (новый), `desktop/package.json` (npm-скрипт `dmg`).

### Фаза 2 — документация `docs/BUILD.md`  `[x]`

- Предусловия, одна команда, путь артефакта, запуск, Gatekeeper-разграничение,
  острый угол про `localhost:8100`, острый угол про Apple events → Finder.
- Файлы: `docs/BUILD.md` (новый), `docs/INSTALL.md` (ссылка).

### Фаза 3 — end-to-end прогон на этой машине  `[x]`

- Backend на :8100 поднят (`docker compose up -d backend`, `/health` → `{"status":"ok"}`).
- Прогон вскрыл три дефекта, которые видно только вживую, все починены (коммит `1d2c710`):
  падение на Apple events, исчезающий `.app` при `--bundles dmg`, копящийся мусор
  `rw.*.dmg` (~47 МБ за каждый упавший прогон).
- `./desktop/scripts/build-dmg.sh --run` → exit 0, оба артефакта на месте, приложение
  открылось (процесс `sdmp-desktop` живой, крэш-репортов нет).
- `.dmg` смонтирован вручную: внутри `SDMP.app` (Mach-O arm64) + симлинк на Applications.
- Повторный прогон подряд — exit 0, оба артефакта, `rw.*.dmg` и временные логи не копятся.
- `xattr` на собранном `.app` → только `com.apple.provenance`, `com.apple.quarantine` нет,
  то есть утверждение доки про Gatekeeper проверено фактически.

## Итог

- **Реализован целиком.** Локальная сборка `.dmg` + запуск воспроизводимы одной командой,
  проверены живым прогоном (четыре подряд), включая фолбэк при запрете Apple events.
- **Проверено не полностью:** сетевой round-trip приложения к backend. Логин-экран
  дёргает API только по сабмиту формы, а ввести пароль в GUI автоматикой нельзя —
  в логах backend после запуска приложения запросов нет, и это ожидаемое поведение,
  а не ошибка. Осталось глазами: залогиниться в открытом приложении и убедиться,
  что запрос уходит на `:8100`.
- **Отложено (Stage 5):** подпись + нотаризация (Developer ID, `notarytool`),
  universal-бинарь и Windows/Linux, CI `release.yml` с checksums, параметризация
  backend через конфигурируемый CSP `connect-src`.
