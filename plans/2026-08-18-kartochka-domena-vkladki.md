# Карточка домена: перенос вкладочного дизайна

## Context

Дизайнер прислал хендофф `Domain Modal.dc.html` + README (распакован в скратчпад,
исходник — `/Users/andrey/Documents/Редизайн с вкладками для страницы.zip`): модалка
домена шириной 920px, разложенная по пяти вкладкам **Overview / Server / Logs /
Template / Custom**, с единым паттерном карточки (шапка-полоска `#eef2f7` + тело),
пилюлями статусов и инлайн-правкой срока в шапке.

Сегодняшняя `DomainDetailModal` — 760px, **без вкладок**, и это было решением
(комментарий в файле, строки 74-93): вкладки `db/ssl/nginx` удалили планом
`plans/2026-08-11-domains-chistka-sloya-ispolneniya.md`, потому что их действия били в
несуществующие роуты. Макет предлагает другие пять вкладок, и две из них (Overview,
Server) — это ровно то, что карточка уже показывает после плана
`plans/2026-08-17-kartochka-domena-svyazi-i-registrar.md` (ряд связей Registrar →
Cloudflare → Server, SSL, Nameservers, Server state с правилом расхождений).

**Задача:** перенести визуальную систему макета и вкладочный каркас, не потеряв
семантику, которую карточка заработала. Разведка показала, что макет рисует Overview и
Server **проще**, чем текущая карточка: в нём нет строк расхождения «при развёртывании:
X», нет легенды `noSnapshot`, нет перечня FTP-аккаунтов, нет `RevealSecret` для пароля,
нет `SSL at provision` и `Last error`. Дизайнер про них не знал. Дословный перенос стёр
бы работу плана от 17.08, поэтому правило переноса такое: **макет даёт вёрстку и
раскладку по вкладкам, существующая семантика переезжает внутрь неё целиком.**

### Решения, принятые в брейншторме (2026-08-18)

1. **Тема — светлая, как в макете.** Хексы инлайном, как везде в приложении. Токены и
   тёмная тема из `design-brief.md` остаются отдельной будущей работой; эта карточка
   тёмного варианта у дизайнера не имеет.
2. **Только вёрстка сейчас, данные потом.** Logs / Template / Custom / Backups — новые
   функции, за которыми нет ни моделей, ни SSH-команд. Они получают **честные пустые
   состояния** по образцу DMCA из самого макета, а не демо-данные с мёртвыми кнопками
   («Run», «Save», 20 выдуманных строк лога). Это прямо следует из принципа 6 CLAUDE.md.
3. **Язык — английский, как в макете.** Новые строки пишем по-английски; двуязычие
   (долг №9 плана от 17.08) при этом не лечим — русские кнопки `Проверить на сервере`,
   `Задать пароль` остаются как есть, отдельным долгом.
4. **Срок истечения правится из шапки** — бэкенд готов (`PUT /domains/{id}`,
   `DomainUpdate.expiry_date`), мутация `useUpdateDomain` уже используется в карточке
   для регистратора.

### Что за макетом есть в приложении (разведка)

| Вкладка  | Данные                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Overview | **есть почти всё** — registrar/CF/server, `sslState`, RDAP-делегирование, NS                                                                        |
| Server   | **есть, кроме бэкапов** — FTP, Site (owner/PHP/БД); бэкапов нет нигде: ни модели, ни поля, ни команды FastPanel в инвентаре `docs/FASTPANEL_CLI.md` |
| Logs     | **есть только метаданные** — `fp_facts.logs[] = {path, exists, size_bytes}`; чтения содержимого нет ни в Rust, ни на бэкенде                        |
| Template | **нет вовсе** — ни модели, ни поля, ни свободного текста у `Domain`                                                                                 |
| Custom   | **нет** — `nginx_presets` есть в БД и в Rust (`render_nginx_snippet`, 4 флага), но ни роутов, ни UI, ни вызова                                      |

## Осознанные отступления от макета

Каждое — потому что макет не знал контекста, и переносить его буквально значило бы
соврать на экране.

1. **Backups → заглушка `COMING SOON`, а не два селекта.** Селекты «Frequency /
   Destination», которые ничего не сохраняют, — это обещание настройки, которой нет.
2. **Logs → реальные четыре файла со своими путями и размерами** (`fp_facts.logs`),
   вместо счётчиков строк (их мы не знаем) и вместо выдуманных строк лога. Тело —
   честное «reading log contents is not wired up yet».
3. **Свежесть снимка на Overview.** Макет ставит «Checked 4h ago · Check on server»
   только на вкладку Server, а карточку SSL кладёт на Overview — при том что SSL там
   читается из ТОГО ЖЕ снимка. Кнопка остаётся одна (на Server), но шапка карточки SSL
   печатает свежесть текстом (`formatAgoStale`), иначе Overview молча выдавал бы
   протухшее измерение за свежее.
4. **Шрифт остаётся текущим** (Inter + системный моно). IBM Plex из макета — это
   вопрос уровня `design-brief.md` §5 ко всему приложению; подключать вебфонт ради
   одной модалки (да ещё сетевой зависимостью в Tauri) неправильно.
5. **Строки «нашей записи»** (`NS:`, `SSL at provision:`, `Last error:`) макетом не
   предусмотрены — остаются на Overview под рядом связей. Причина их появления описана
   в `SSL_PROVISION_ALARM` (`DomainDetailModal.tsx:17-57`) и не отменена.

## Фазы

### Фаза 1 — каркас `[ ]`

- **`frontend/src/components/ui/Tabs.tsx`** (новый примитив). Подчёркнутые вкладки по
  спеке макета: 14px, `padding:10px 14px 12px`, активная — 600 `#0f172a` + 2px нижняя
  граница, неактивная — 500 `#64748b`. В отличие от трёх существующих копий
  (`pages/Activity.tsx:71-77`, `pages/Settings.tsx:112-116`,
  `pages/ServerDetail.tsx:888-893` — все `<div onClick>` без ролей) новый примитив
  делает `role="tablist"/"tab"/"tabpanel"`, `aria-selected`, стрелки влево/вправо.
  Существующие три страницы **не трогаем** — это чужой скоуп.
- **`SectionCard`** в `Primitives.tsx` — единый паттерн карточки макета: рамка
  `#dbe3ee`, радиус 12, фон `#fbfcfe`, шапка-полоска `#eef2f7` с uppercase-титулом
  13/700 и правым слотом (пилюля или мета-текст), тело `16px 18px`. Существующие
  `Card/CHd/CTi/CBo` дают другую геометрию и используются десятками мест — новый
  компонент рядом, старые не переписываем.
- **`Modal`** получает необязательный проп `header?: React.ReactNode`, заменяющий
  штатную строку «title + ✕». Дефолт не меняется, остальные вызовы не затрагиваются.
- Ширина карточки 760 → 920. Дисциплина `minmax(0,1fr)` / `minWidth:0` /
  `overflowWrap:"anywhere"` сохраняется — `Modal` держит `overflowY:auto`, из-за чего
  `overflow-x` вычисляется в `auto` (см. долг плана 17.08).

### Фаза 2 — шапка карточки `[ ]`

Новый `frontend/src/components/domains/DomainModalHeader.tsx`: eyebrow `DOMAIN` +
`DomainStatusBadge`, имя домена 24/700, мета-строка (SSL-бейдж из `sslState` + срок), ✕
34px. Заменяет `DomainSummaryBar` (его содержимое переезжает в шапку целиком; файл
удаляем, тесты переводим на новую разметку).

Новый `DomainExpiryField.tsx` — инлайн-правка: кнопка с пунктирным подчёркиванием →
`<input type="date">` → `useUpdateDomain({expiry_date})`, закрытие по blur, пустое
состояние «set date». Формат вывода — существующий `lib/domainExpiry` + `fmtDate`, чтобы
срок в карточке и в колонке списка не разошлись.

**Долг №4 плана 17.08 закрывается здесь заодно:** `sslState` считается один раз в
модалке и раздаётся вниз — теперь его потребителей два (шапка и карточка SSL на
Overview), и «сойдётся само» перестаёт быть приемлемым.

### Фаза 3 — вкладка Overview `[ ]`

`components/domains/tabs/DomainOverviewTab.tsx`:

- Ряд связей — существующий `DomainLinks` (+ `DomainRegistrarField`,
  `DomainCloudflareField`) в трёх `SectionCard`. Логику полей не трогаем.
- Строки «нашей записи» под рядом (см. отступление 5).
- **SSL** — `SectionCard` с kv-сеткой `80px 1fr`: State (бейдж), Expires, Issuer. Это
  SSL-часть, вынутая из `DomainServerFacts`, вместе с её `FactRow`/`DRAW`-логикой
  расхождений. В правом слоте шапки — свежесть снимка (отступление 3).
- **Nameservers** — существующий `DomainNsPanel` в `SectionCard`, пилюля делегирования
  (`nsDelegation`) переезжает в правый слот шапки. Textarea, «Restore from Cloudflare»,
  push-кнопка, строки-объяснения и ошибка из `MutationCache` сохраняются полностью.
- **DMCA** — заглушка с пилюлей `COMING SOON`, текст из макета.

### Фаза 4 — вкладка Server `[ ]`

`DomainServerFacts.tsx` (568 строк) распиливается; общее — `FactRow`, `DRAW`,
`HasSnapshot`, `Row`, `Note`, `SubTitle` — уезжает в `domains/facts/` и
переиспользуется обеими вкладками.

- Верхняя строка: `formatAgoStale` слева, `Проверить на сервере` (desktop-only) справа.
- `fp_check_error`-алерт и легенда `noSnapshot` — как есть.
- **FTP Access** — Host (IP сервера), Port 21, Login, Password (`FtpPassword` +
  `RevealSecret` + «Задать пароль»), плюс перечень «Accounts on server» под гейтом
  `ftpRosterAdds`.
- **Site** — Path, Owner, PHP, Databases, DB user. Строка `Logs` отсюда уходит на
  вкладку Logs (дубля быть не должно).
- **Backups** — заглушка `COMING SOON` (отступление 1).

### Фаза 5 — вкладка Logs `[ ]`

`tabs/DomainLogsTab.tsx`. Чипы по `fp_facts.logs[]`: имя файла выводим из пути
(`-frontend.access.log` → «Frontend access»), в бейдже — размер (`exists ? size : —`),
не число строк. Под чипами — полный путь моно 12px. Тело — честное состояние: «Reading
log contents is not wired up yet», а при `!fp_facts_at` — «Never checked» с той же
кнопкой снятия снимка, что на Server. Тёмная консоль и таблица access из макета
реализуются, когда появится чтение (отдельная функция: новая Tauri-команда с `tail` по
SSH; на бэкенд это не ложится — zero-knowledge, SSH-пароль это блоб).

### Фаза 6 — Template и Custom `[ ]`

По одной заглушке-`SectionCard` на вкладку, тексты по образцу DMCA. Custom объясняет,
чем станет: «Presets - saved multi-step actions you can run on this domain».

### Фаза 7 — тесты `[ ]`

Существующие наборы (`DomainDetailModal.overview.test.tsx` 356,
`.cfzone.test.tsx` 701, `.setns.test.tsx` 679, `DomainServerFacts.test.tsx` 540)
сломаются: содержимое ушло под вкладки. Правка — хелпер `openTab(name)` в общем
`test-utils` и точечные вставки, **без переписывания утверждений**: они охраняют
поведение, которое эта работа менять не должна.

Новое покрытие: клавиатура и роли `Tabs`; правка срока (оптимистичный рендер, ошибка
мутации, пустое состояние); чипы Logs на снимке и без снимка; неразъезжаемость
SSL-бейджа шапки и карточки SSL (один `sslState` на модалку).
