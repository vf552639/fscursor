# План: вкладка Logs — чтение хвоста лог-файла

**Дата:** 2026-08-19
**Связь с бизнесом:** «пульт управления инфраструктурой» обязан отвечать на вопрос
«почему сайт отдаёт 500», не выгоняя пользователя в терминал. Сегодня вкладка Logs
показывает четыре имени файла и говорит «reading log contents is not wired up yet» —
то есть называет предмет и не даёт его открыть.

## Context

### Что есть сегодня

`DomainLogsTab` (`frontend/src/components/domains/tabs/DomainLogsTab.tsx`) рисует чипы по
`fp_facts.logs[] = {path, exists, size_bytes}` — это всё, что о логах знает система.
Список строит `read_log_paths` (`desktop/src-tauri/src/ssh/fastpanel_facts.rs:533`): четыре
кандидата `<owner_home>/logs/<domain>-{frontend,backend}.{access,error}.log`, по ним один
`for`-цикл с `test -f` и `stat -c %s`. Снимок уезжает на сервер в JSON-колонку
`domains.fp_facts` через `POST /domains/{id}/facts`.

Чтения СОДЕРЖИМОГО нет нигде: ни в Rust, ни на бэкенде. Заглушка на вкладке — честная,
и снять её надо не убрав фразу, а сделав то, о чём она говорит.

### Разведка: отдаёт ли логи сам FastPanel CLI (2026-08-19)

**Нет.** Проверено по официальной базе знаний вендора (`kb.fastpanel.direct`):

- раздел CLI состоит из шести страниц — Introduction, Websites, Databases, Users, Email,
  User transfer. **Страницы про логи среди них нет**;
- у `mogwai sites` (тот же бинарь, что наш `/usr/local/fastpanel2/fastpanel`)
  документированы пять подкоманд — `list`, `create`, `delete`, `update`, `batch-update`.
  Ни подкоманды, ни флага про логи;
- страница вендора про логи сайта описывает **модуль веб-панели** и анализатор AWStats;
  ни команды, ни путей к файлам там нет;
- страница troubleshooting не даёт ни одной консольной команды для чтения логов.

Побочно разведка **подтвердила первоисточником набор из четырёх файлов**: вендор
перечисляет ровно frontend access (Nginx), frontend error (Nginx), backend access
(Apache, PHP-FPM), backend error (Apache, PHP-FPM) — буква в букву те четыре, что строит
`log_candidates`. До этого набор держался на одном живом сервере (discovery 2026-08-16).

Непроверенное, на котором ничего не построено: в поисковой выдаче попался сторонний блог
с листингом `mogwai --help` (`help`, `backup:plan`, `scan:virtualhost`,
`generate_templates`, `state`, `panel`, `sessions`, `sites`, `fcgid_cleaner`, `chpasswd`,
`schema`, `services`, `cron`) — логов нет и там, но саму страницу открыть не удалось
(домен не резолвится). Косвенно правдоподобен: первые три имени совпадают с тем, что
`docs/FASTPANEL_CLI.md` §0 видел под непривилегированным пользователем панели.

**Вывод: читаем файлы напрямую**, как уже читаем SSL через `openssl` и раскладку через
`test -f`. Живой прогон `fastpanel --help` из блокирующего вопроса стал дешёвой сноской
(фаза 6).

### Решения, принятые в брейншторме (2026-08-19)

1. **Объём — хвост и обновление.** Показать последние N строк выбранного файла кнопкой
   Refresh. Ни поиска, ни сводки, ни `tail -f` — каждое отдельным планом.
2. **Файлы — только четыре текущих.** Ротация (`.1`, `.N.gz`) и внешние логи
   (`letsencrypt.log`, глобальный nginx, php-fpm) — вне объёма.
3. **Труба — Rust-команда**, а не фронт + `ssh_exec`. Два свойства, которых у второго
   варианта нет по построению: пароль не появляется в куче JS (там его нельзя занулить),
   и путь ограничивается списком из снимка. Плюс цепочка «домен → сервер → блоб» в Rust
   уже написана и оттестирована (`domain_read_facts`), а во фронте её пришлось бы
   собирать с нуля — метрики сервера стартуют от карточки СЕРВЕРА, где сервер уже под
   рукой, здесь стартовая точка другая.
4. **Показ — сырые строки моноширинным.** Формат access-лога не сверен, а `.includes`
   директив логов не содержит (discovery: `grep` вернул exit 1). Разбор в колонки или
   раскраска по угаданной позиции поля — выдуманный диагноз (принцип №6 CLAUDE.md).
5. **Аудита нет.** Снимок пишется в аудит потому, что меняет строку в БД
   (`POST /domains/{id}/facts` и есть запись `domain.read_facts`). Хвост не меняет
   ничего и никуда не едет — новый роут ради сетевого круга на каждый Refresh не заводим.
   Пересмотреть, когда у вкладки появятся мутации.

### Главное ограничение: содержимое не уезжает на сервер

В access-логе лежат IP, URL с query string и user-agent — **чужие персональные данные**.
`fp_facts` — открытая JSON-колонка в Postgres. Значит хвост живёт только в памяти
десктопа: ни в `fp_facts`, ни в SQLCipher-кэше, ни в аудите. В вебе вкладка остаётся
такой, как сейчас (принцип №3: десктоп выполняет, веб смотрит).

## Acceptance criteria (что значит «готово»)

- [ ] **Живая приёмка человеком (не проводилась).** В десктопе: открыть карточку домена
      со снимком → вкладка Logs → выбрать чип → Refresh → на экране последние строки
      этого файла с сервера. Всё остальное ниже закрыто кодом и автотестами; это —
      единственное, что автотест доказать не может, потому что требует живого сервера.
- [x] Пустой файл (`0 B`) даёт «Log file is empty», а не пустую консоль без объяснения.
- [x] Чип с `exists: false` не ходит на сервер вовсе — говорит, что файла нет.
- [x] Смена чипа сбрасывает прочитанное: строки одного файла не остаются под подписью
      другого.
- [x] Запрос пути, которого нет в `fp_facts.logs[].path` этого домена, отвергается **до
      коннекта** и с сервера ничего не читает.
- [x] Провал чтения хвоста НЕ двигает `fp_checked_at`, не пишет `fp_check_error` и не
      трогает `fp_facts`: снимок и хвост — разные измерения.
- [x] В вебе кнопки Refresh нет; вместо неё фраза про десктоп.
- [x] Ни строки лога не попадает на сервер, в SQLCipher-кэш и в аудит.
- [x] `npm test` и `cargo test` зелёные.

## Edge cases (продумать заранее)

- **Лог на 2 ГБ.** `tail -n 200` без байтового капа прочитает файл целиком — кап стоит
  ПЕРВЫМ (`tail -c` до `tail -n`).
- **Одна строка на 200 МБ** (PHP-трейс в error-логе, JSON-дамп). Байтовый кап её режет;
  обрезок первой строки выбрасываем — обрезок не строка.
- **Ноль данных:** файла нет / файл пуст / снимка нет / `logs[]` пуст (четыре причины
  пустоты, уже разобранные в комментарии вкладки) — у каждого свой ответ на экране.
- **Файл исчез между снимком и Refresh** (сайт переехал, владелец сменился): команда
  отвечает `#sdmp:missing`, вкладка говорит про отсутствие файла, чип при этом ещё
  показывает старый размер из снимка — это нормально, размер помечен возрастом снимка.
- **Двойной клик по Refresh** — гейт `runExclusive` по ключу «домен + путь».
- **Смена чипа во время чтения** — результат обязан лечь под ТОТ файл, для которого
  запрошен; иначе строки backend.error окажутся под подписью frontend.access.
- **Zero-knowledge:** в argv команды нет пароля (читаем, не мутируем) — значит
  `opaque_exit` здесь не нужен и текст ошибки можно отдавать наружу целиком. Но наружу
  — это ТОЛЬКО в десктоп: на сервер не уходит ничего.
- **Не-UTF-8 в логе** (битые байты, чужая кодировка): `String::from_utf8_lossy` уже стоит
  в `SshSession::exec` — строки приедут с `U+FFFD`, а не уронят команду.
- **Обратная совместимость:** снимок, снятый до появления `logs` в контракте, приезжает
  без поля. `?? []` во вкладке это уже глотает; гейт пути на таком снимке отвергнет всё
  — и правильно, чипов там тоже нет.

## Фазы

### Фаза 1 — модуль чтения хвоста в Rust `[x]`

**Новый файл `desktop/src-tauri/src/ssh/fastpanel_logs.rs`** + строка в
`desktop/src-tauri/src/ssh/mod.rs`.

Отдельный файл, а не дописка в `fastpanel_facts.rs`, по той же причине, по какой сам
`fastpanel_facts.rs` отделён от `fastpanel.rs`: тот про **снимок**, который уезжает на
сервер и в БД, этот — про чтение по требованию, которое не уезжает никуда. Разная цена
ошибки и разные правила. Плюс в facts уже 990 строк.

Константы:

```rust
/// Байтовый потолок на одно чтение. Стоит ПЕРВЫМ в конвейере: `tail -n` по
/// логу в гигабайты прочитал бы файл целиком.
pub const LOG_TAIL_BYTES: u64 = 256 * 1024;

/// Сколько строк показываем. 200 — экран прокрутки, а не «немного»: меньше не
/// покрывает всплеск ошибок, больше не читается глазами и не помогает.
pub const LOG_TAIL_LINES: usize = 200;

/// Предел на exec чтения хвоста. Меньше `FACTS_EXEC_TIMEOUT` (45 c): здесь одна
/// команда над одним файлом, а не листинг сотни доменов.
pub const LOG_TAIL_EXEC_TIMEOUT: Duration = Duration::from_secs(30);
```

Тип результата (`Serialize`, уходит только в UI — на сервер НЕ уходит, и это записать
комментарием прямо у типа):

```rust
pub struct LogTail {
    pub exists: bool,
    pub size_bytes: Option<u64>,
    pub lines: Vec<String>,
    /// Кап сработал: показано не с начала файла.
    pub truncated: bool,
}
```

`build_log_tail_cmd(path: &str) -> String` — форма с маркерами по образцу
`COLLECT_METRICS_COMMAND`, включая `#sdmp:end` как подпись «вывод доехал целиком»:

```
if [ ! -f P ]; then echo '#sdmp:missing'; else
  printf '#sdmp:size %s\n' "$(stat -c %s P)"
  echo '#sdmp:tail'
  tail -c 262144 P | tail -n 200
fi
echo '#sdmp:end'
```

`P` — `q(path)` (`shell_escape::escape`, уже импортируется из `ssh::fastpanel`). Правило
§7.2 `docs/FASTPANEL_CLI.md`: прямой интерполяции без `q()` быть не должно.

Размер снимается заново, а не берётся из снимка: он и есть ответ на вопрос «сработал ли
кап», и он свежий, тогда как снимок бывает недельной давности.

`parse_log_tail(output: &str, cap: u64) -> Option<LogTail>` — чистая функция:

- нет `#sdmp:end` → `None` (разбор отказывает целиком, как у метрик: неполный вывод не
  спасается, иначе оборванный посреди строки лог выглядел бы как короткий);
- `#sdmp:missing` → `LogTail { exists: false, .. }`;
- `#sdmp:size N` → `size_bytes`; всё после `#sdmp:tail` и до `#sdmp:end` — строки;
- `size > cap` → `truncated: true` и **первая строка выбрасывается** (обрезок).

`read_log_tail(s: &mut impl Exec, path: &str) -> Result<LogTail, SshError>` — один exec,
разбор, `SshError::Session("unparsable log tail output")` на `None`.

**Тесты (`cargo test`):**

- `build_log_tail_cmd` квотирует путь: подать `/tmp/a; rm -rf /` и убедиться, что в
  команде нет неквотированной точки с запятой (образец —
  `read_commands_argv_has_no_secret` в `fastpanel_facts.rs`);
- `parse_log_tail` на четырёх формах: обычный вывод, `#sdmp:missing`, вывод без
  `#sdmp:end` → `None`, `size > cap` → `truncated` и первая строка съедена;
- пустой файл: `size 0`, ноль строк, `exists: true` — это НЕ `missing`;
- `LOG_TAIL_BYTES` и `LOG_TAIL_LINES` присутствуют в тексте команды (иначе правка
  константы молча разошлась бы с командой).

### Фаза 2 — Tauri-команда `domain_read_log_tail` `[x]`

**`desktop/src-tauri/src/commands/domain_logs.rs`** (новый) + `commands/mod.rs` +
`invoke_handler![]` в `desktop/src-tauri/src/lib.rs` (рядом с
`commands::domain_facts::domain_read_facts`).

Сигнатура: `domain_read_log_tail(app, user_id, domain_id, path, handle, api) -> LogTail`.

Голова копируется с `domain_read_facts` (`commands/domain_facts.rs:57-120`) до коннекта
включительно: `keychain::load_vault_key` → `cache::open` → `get_row_fields("domains")` →
`server_id` → `get_row_fields("servers")` → `blob_plaintext` → `key.zeroize()` → host /
port / ssh_user → `drop(conn)` → `ssh_connect_session_with_timeout` →
`password.zeroize()`.

**Отличие первое — гейт пути.** Перед коннектом: достать из строки домена в кэше
`fp_facts.logs[].path` и потребовать, чтобы запрошенный `path` был среди них. Не совпал —
`CommandError::Api("path is not a log file of this domain")`, **до** открытия сессии.
Ровно тот список, который вкладка нарисовала чипами: нет снимка → нет чипов → нечего и
читать. Это то, ради чего в брейншторме выбран Rust вместо `ssh_exec`, — вынести гейт
комментарием, иначе следующая правка «упростит» его обратно.

**Отличие второе — никакого write-back.** Ни `fp_facts`, ни `fp_facts_at`, ни
`fp_checked_at`, ни `fp_check_error`. Ни на успехе, ни на провале. Провал чтения хвоста —
не провал снимка; сдвинуть `fp_checked_at` значило бы записать попытку снять снимок,
которой не было. Соответственно `api: State<ApiClient>` команде нужен только ради
`blob_plaintext` — и это стоит сказать прямо, потому что у соседней команды тот же
параметр служит write-back'у.

`HOST_KEY_UNKNOWN` пробрасывается как есть (та же строка-сентинел, тот же разбор во
фронте).

Таймауты: `LOG_TAIL_SESSION_TIMEOUT = 60 s`, exec — `LOG_TAIL_EXEC_TIMEOUT = 30 s`.

**Тесты:**

- соотношение таймаутов (`session > exec`) — образец
  `session_timeout_exceeds_the_read_exec_budget` в `commands/domain_facts.rs`;
- гейт пути: чистая функция `path_is_known(facts_json, path) -> bool`, вынесенная из
  команды ради теста (сама команда неюнит-тестируема — ей нужны keychain и SSH). Случаи:
  путь из списка → true; чужой путь → false; `fp_facts` без `logs` → false; `fp_facts`
  = `null` → false; путь с отличающимся регистром → false (пути в Linux
  регистрозависимы, «почти совпал» — это не совпал).

### Фаза 3 — фронт: провод и хук `[x]`

**`frontend/src/lib/domainFacts.ts`** — добавить wire-тип `LogTail`, точно повторяющий
serde-форму Rust (там же, где живёт `DomainFacts`, и по той же причине: это контракт
провода, а не деталь компонента).

**`frontend/src/api/domains.ts`** — по образцу `runReadDomainFacts` / `useReadDomainFacts`:

```ts
export const readLogTailKey = (domainId: number, path: string) => [...];
export function useReadLogTail(domainId: number, path: string | null): {
  pending: boolean;
  tail: LogTail | null;
  error: string | null;
  run: () => void;
};
```

Отличие от `useReadDomainFacts`: тот **ничего не возвращает наверх** (результат едет в БД
и приезжает ресинком, поэтому хук лишь дёргает `invalidateQueries`). Здесь результата в
БД нет и не будет — значит хук обязан держать `tail` и `error` у себя, в стейте. Это и
есть техническое следствие решения «содержимое не уезжает на сервер», и его надо
записать комментарием у хука.

Ключ гейта — **домен + путь**: два разных файла читать одновременно можно, один и тот же
дважды — нет.

`invokeIfTauri`, а НЕ `invokeSynced`: `syncLocalCache()` перед каждым Refresh — это
круг в сеть ради строки, которая уже в кэше (её только что прочитала вкладка, чтобы
нарисовать чипы). Снимок тянуть заново незачем — гейт пути сверяется с тем же кэшем,
что нарисовал чип, и рассинхрона между ними по построению нет.

`queryClient.invalidateQueries` **не зовём** — на сервере ничего не изменилось.

### Фаза 4 — вкладка `[x]`

**`frontend/src/components/domains/tabs/DomainLogsTab.tsx`.**

Кнопка `Refresh` — в ряд с полным путём выбранного файла (не в `SnapshotLine`: та про
снимок, а Refresh про содержимое; смешать их значило бы обещать, что Refresh обновит и
размеры чипов). Кнопка снимка остаётся ровно там, где стоит (только при `noSnapshot`), и
своё обоснование в комментарии не теряет.

Состояния тела — по порядку проверки:

| Условие | Что на экране |
|---|---|
| `noSnapshot` | как сейчас: «none has been taken yet» |
| `logs.length === 0` | как сейчас: «we do not know where its logs are» |
| `!isTauri()` | «Reading log contents requires the desktop app» (принцип №3) |
| `!selected.exists` | «This file does not exist on the server» — на сервер не ходим |
| читаем | pending-состояние кнопки |
| ошибка | текст ошибки над консолью, консоль не стираем |
| не читали | «Press Refresh to read the last 200 lines» (**вместо** сегодняшнего «not wired up yet») |
| `tail.lines.length === 0` | «Log file is empty» — состояние из макета |
| иначе | консоль |

Смена чипа сбрасывает прочитанное. Реализация: хранить `tail` рядом с путём, для которого
он получен, и показывать только при совпадении с `selected.path` — тогда и результат
чтения, вернувшийся ПОСЛЕ переключения чипа, не ляжет под чужую подпись. Проверкой
совпадения, а не `useEffect`-сбросом: сброс по эффекту отработает на такт позже, и один
кадр строки простоят под чужим именем.

**Консоль:** системный моно (`ui-monospace`, как у пути ниже чипов и как везде в
приложении — вебфонт ради одной модалки не подключаем, отступление №4 плана от 18.08),
12px, `white-space: pre`, `overflow-x: auto` **внутри своего блока**. Горизонтальную
полосу `design-brief.md` §11 запрещает странице, не блоку; у `Modal` стоит
`overflowY: auto`, поэтому неограниченная консоль дала бы полосу всей карточке.
Фиксированная высота, прокрутка к низу после загрузки (новые строки внизу, как в
терминале).

Строки не подсвечиваем и не раскрашиваем — см. решение №4 брейншторма.

Шапка консоли: `last 200 lines · 47 KB` + `truncated` когда кап сработал. Свежий размер
печатается **здесь, а не в бейдже чипа**: один обновлённый чип рядом с тремя из старого
снимка врал бы про общий возраст, а возраст у чипов один на всех и назван
`SnapshotLine`.

## Явно откладываем (и почему именно)

- **Ротация (`.1`, `.N.gz`).** Требует расширения СНИМКА: сегодня `read_log_paths` строит
  четыре кандидата, а ротацию видно только `ls`. Это правка контракта `fp_facts` —
  отдельная работа со своей миграцией смысла.
- **Внешние логи** (`/var/log/letsencrypt/letsencrypt.log` — прямо объясняет провал
  выпуска SSL, глобальный nginx, php-fpm, `/var/log/fastpanel2`). Самое полезное из
  отложенного, но эти файлы **общие на сервер**: в карточке ОДНОГО домена они покажут
  чужие строки, и место им скорее на карточке сервера.
- **Поиск/фильтр** (`grep` по файлу). Первый случай, когда в argv команды поедет строка,
  набранная человеком; нужен собственный тест на инъекцию, а не только `q()`.
- **Сводка по access-логу** (топ статусов/URL/IP). Заблокирована несверенным форматом:
  `.includes` директив логов не содержит, а позиции полей мы не знаем. **Заметка на
  будущее:** в `sites list --json` есть `log_rotate.awstats` (на нашем сервере `false`)
  — включённый AWStats считает агрегаты сам, и это готовый источник вместо `awk` по
  угаданным позициям.
- **Живой `tail -f`.** `SshSession::exec` буферизует весь вывод в `Vec` и отдаёт одним
  куском; поток потребовал бы канала данных в Tauri-события — плумбинг сам по себе
  больше, чем весь этот план.
- **Download.** По той же причине, но острее: `exec` в память + лог на 500 МБ = мёртвый
  десктоп. Честная выгрузка — SFTP-поток в файл, а не `cat`.

### Отступления и решения сверх плана

1. **`#sdmp:end` ищется с КОНЦА вывода, а после `#sdmp:tail` маркеры не разбираются.**
   Строка лога вправе выглядеть как наш маркер (в error-логе бывает что угодно), а наш
   `echo` заведомо последний. Иначе строка `#sdmp:end` внутри лога обрезала бы хвост.
   Под тестом.
2. **Гейт пути стоит не просто «до коннекта», а до расшифровки блоба и до чтения строки
   сервера.** На отвергнутом пути в сеть не уходит вообще ничего — даже запрос блоба.
3. **`path_is_known` пускает путь с `exists: false`** — гейт про членство в списке снимка,
   а «файла нет» скажет сама команда маркером `#sdmp:missing`. Это и есть плановый edge
   case «файл исчез между снимком и Refresh», и под него добавлено СВОЁ состояние тела
   вкладки (`tail.exists === false`), которого в таблице плана не было.
4. **Шапка консоли печатает фактическое число строк** (`last 3 lines · 47 KB`), а не
   литерал 200: «last 200 lines» под файлом из трёх строк было бы обещанием, а не отчётом.
5. **Совпадение пути с результатом проверяется в ХУКЕ, а не в компоненте.** Сигнатура из
   плана (`{pending, tail, error, run}`) пути наружу не отдаёт — значит сверять может
   только тот, у кого лежит стейт. Поведение то же, что требовал план.
6. **Кнопка Refresh на `exists: false` не прячется, а гаснет** (с `title`, объясняющим
   почему), — тело вкладки при этом говорит словами. Команда не зовётся, под тестом.
7. **Консоль светлая (slate), а не тёмная из макета**, и строки не раскрашены — формат
   access-лога не сверен ни с одной директивой на сервере.
8. `<pre>` получил `tabIndex={0}` и `aria-label="Log contents"`: прокручиваемая область
   недоступна с клавиатуры, пока не станет фокусируемой.
9. **`truncated` зависит от того, что `stat` отдал число.** При `size_bytes: null` флаг
   остаётся `false` и первая строка не выбрасывается — теоретически может оказаться
   обрезком. Обратный выбор врал бы на каждом обычном чтении; состояние видно на проводе.
