# План: Cloudflare ↔ Domains — живой матч и синхрон (Кейс 1)

**Дата:** 2026-08-13
**Источник:** `task8.md` (корень), Кейс 1. Второй половине — Кейсу 2 — отведён отдельный
план `2026-08-13-domains-full-setup.md`.
**Ветка:** `feat/domains-cloudflare-match`

## Context (зачем)

В строке вкладки **Domains** колонка «Cloudflare» показывает аккаунт только из
персистентного `cloudflare_account_id` (`DomainRow.tsx:108` читает `cfAccount`). Вкладка
**Cloudflare** знает раскладку шире — из живого `cf_list_zones` (`useCloudflareZones`), —
поэтому в строках стоит «—» там, где аккаунт по факту известен. Пользователь подтвердил
скриншотами: зоны на вкладке Cloudflare живые (настоящие zone-id, статус `Active`), а
колонка в строках пустая → у доменов в БД нет `cloudflare_account_id`.

Решения пользователя, зафиксированные на макете:
- Подсказка в строке визуально **отличается** от сохранённой привязки; неоднозначность
  **не угадывается** и не показывается вовсе.
- Синхрон — **только привязка** (`account_id`+`zone_id`); NS пушится отдельно, из Overview.

Zero-knowledge (жёсткое ограничение): токен Cloudflare живёт только в десктопе; бэкенд в
Cloudflare не ходит. Любое чтение зон — Tauri-команда, значит вся фича desktop-only, а в
вебе колонка остаётся прочерком, как сейчас.

## Acceptance criteria

- [ ] Домен, чьё имя совпало ровно с одной живой зоной, показывает имя аккаунта подсказкой
      (курсив + приглушённый цвет, без чипа), с `title` про «в базе не сохранено».
- [ ] Сохранённая привязка выглядит как раньше (обычный текст) — подсказку от факта видно.
- [ ] Совпадение в 2+ аккаунтах → «—» без меток.
- [ ] Аккаунты, чьи зоны не прочитались, названы баннером над таблицей.
- [ ] Кнопка «Синхронизировать с Cloudflare» гоняет привязку по всему списку и отчитывается
      существующим `CloudflareBindBanner`.
- [ ] Overview карточки домена: селект аккаунта вместо сырого id, дорезолв `zone_id`,
      NS-запись зоны рядом со сверкой с регистратором, вкладки `ns` больше нет.
- [ ] Тест на число рендеров `DomainRow` продолжает проходить (мемоизация не сломана).

## Edge cases

- Веб (`!isTauri()`): карта матчей пуста, баннера нет, кнопка синхрона скрыта/дизейблена.
- Нулевой список аккаунтов CF: подсказок нет, баннера «не прочитаны» нет.
- Сотни доменов × десятки зон: один мемоизированный прогон `matchDomainsToZones`,
  результат — стабильная ссылка на `Map`.
- Двойной клик по «Синхронизировать»: гейт «один прогон за раз» уже есть в
  `useCloudflareBind` (заявка в `MutationCache` под `CF_BIND_KEY`).
- Домен с аккаунтом, но без `cloudflare_zone_id` — дорезолв в Overview (Фаза 3).

## Фазы

### Фаза 1 — Живой матч как подсказка в строке `[x]`

**Новый хук** `frontend/src/hooks/useDomainZoneMatches.ts`:
- `useCloudflareAccounts` + живые зоны каждого активного аккаунта через `useQueries`
  поверх существующего `zonesQuery(accountId)` (`api/cloudflare.ts`). Desktop-only
  (`enabled: isTauri()`); в вебе карта пустая → «—» как сейчас.
- Один мемоизированный прогон **`matchDomainsToZones(domains, zonesByAccount)`**
  (`lib/cfZoneMatch.ts`, переиспользуем как есть: даёт `matched`/`ambiguous`/`none`/
  `skipped`).
- Возврат — **стабильная** `Map<number, RowCfHint>`, где hint уже резолвит объект
  аккаунта: `{ outcome:"matched", account } | { outcome:"ambiguous", accountIds }`.

**`DomainRow.tsx`** (ячейка Cloudflare, строка 108) — проп `cfHint?: RowCfHint`:
- есть `cf` (сохранённый) → `{cf.name}` как сейчас;
- `matched` → имя аккаунта **курсивом и слегка приглушённо, БЕЗ метки-чипа** + `title`
  «Совпало с зоной Cloudflare — в базе не сохранено. Нажми Синхронизировать»;
- `ambiguous` / `none` / нет данных → «—» (БЕЗ метки «неоднозначно»).
- Колонку NS в таблицу **не добавляем**. Легенды под таблицей **нет**.

**`DomainTable.tsx`** — проп `zoneHints`, проброс `zoneHints.get(d.id)` в строку.
**`Domains.tsx`** — вычислить hints поверх `domainsData`, передать в таблицу.

**Непрочитанные аккаунты.** Хук смотрит ошибки per-account запросов зон (`useQueries`);
если у аккаунта зоны не прочитались (сломан токен), над таблицей тихий баннер
«N аккаунтов не прочитаны — совпадения по ним не показаны», чтобы «—» не читалось
как «Cloudflare нет».

**Гард мемоизации:** одна мемо-карта, ссылка стабильна — тест на число рендеров
`DomainRow` должен продолжать проходить.

### Фаза 2 — Кнопка «Синхронизировать с Cloudflare» `[x]`

Переиспользуем `useCloudflareBind` → `autoBindDomainsToCloudflare` (уже пишет
`account_id`+`zone_id`, идемпотентно, репорт через `CloudflareBindBanner`, гейт «один
прогон за раз»). Сегодня зовётся только по выделенным.
- `DomainsHeader.tsx` — заметная кнопка «Синхронизировать с Cloudflare».
- `Domains.tsx` — `onClick={() => void cfBind.run(domainsData, "manual")}` (весь список),
  `disabled={cfBind.pending}`, прятать/дизейблить под `!isTauri()`.
- Результат — существующий баннер. **NS не трогаем.**

### Фаза 3 — Overview: аккаунт + NS в одном месте `[x]`

`DomainDetailModal.tsx`. **Слить NS в Overview**: отдельной вкладки `ns` больше нет — её
содержимое переезжает в Overview (таб-свитчер убрать).
- **Пикер аккаунта.** Заменить `<Field k="Cloudflare" v={cloudflare_account_id} />` на
  селект (`useCloudflareAccounts`, по имени — закрывает долг «сырой id»).
  На выбор — `useUpdateDomain` (`PUT /domains/{id}`, `{ cloudflare_account_id }`).
- **Дорезолв зоны.** При выборе аккаунта И для домена, у которого аккаунт уже есть, а
  `cloudflare_zone_id` пуст, резолвить зону точным совпадением имени (`useCloudflareZones`
  + `normalizeZoneName`); однозначно нашли → сохранить `zone_id`. Чинит `skipped`-домены.
- **NS-запись + делегирование.** Показать nameservers зоны (`useZoneNameservers` по
  `account_id`+`zone_id`) и **сверить** с реальными NS у регистратора (`useRegistrarDomains`
  → `nameservers` домена): бейдж «делегировано / pending / расходится». Кнопка «Прописать NS
  у регистратора» (существующий `useSetNameservers`), дизейбл если регистратор без API
  (`registrarSupportsNsApi`, общий с Кейсом 2) или зона не резолвится.

## Гарды корректности

- Подсказка ≠ факт: отдельный стиль + `title`; сохранённая привязка как раньше.
- Неоднозначность не угадываем (зеркалит `cfZoneMatch`).
- Мемо-строки не ломать (есть тест на число рендеров).
- Zero-knowledge: бэкенд не ходит в Cloudflare; зоны/NS — только десктоп.
- Аккаунт с непрочитанными зонами не даёт подсказок и назван баннером.

## Верификация

1. **Показ:** аккаунт CF с валидным токеном, домены = именам зон → колонка сама показывает
   аккаунт подсказкой, без кликов. Веб → «—».
2. **Синхрон:** «Синхронизировать с Cloudflare» → баннер «N of M linked», подсказки
   становятся сохранёнными.
3. **Неоднозначность:** одноимённая зона в 2 аккаунтах → строка «—», sync пропускает.
4. **Overview:** выбрать аккаунт → сохранилось, зона дорезолвилась; NS-запись видна, бейдж
   делегирования верный; кнопка «Прописать NS» дизейблится для регистратора без API.
5. **Непрочитанный аккаунт:** сломан токен → баннер «N аккаунтов не прочитаны».
6. Тесты точечно (`npm test` во фронте флакует таймаутами, долг Д12): новый хук матчей,
   рендер подсказки в `DomainRow`, тест мемо-рендеров.

### Фаза 1 — что вышло по факту

Хук `hooks/useDomainZoneMatches.ts` возвращает не голую `Map`, а
`{ hints, unreadAccounts }`: ошибки per-account запросов зон видны только внутри хука, а
баннер непрочитанных требуется той же фазой — второй хук с теми же подписками был бы
дублированием ради формы возврата. Ссылка на весь объект стабильна (кэш-ячейка на `useRef`
со сравнением зависимостей по ссылкам; `useMemo` не годится — число зависимостей равно числу
аккаунтов и меняется между рендерами). Тест на число рендеров `DomainRow` зелёный, к нему
добавлен кейс именно с подсказками.

Ревью качества нашло дефект, которого спека не требовала, но ради которого фича и делается:
в react-query v5 фоновый провал **сохраняет `data` и ставит `error`**, то есть аккаунт с
протухшим токеном, чьи зоны прочитались в начале сессии, уходил в ветку `data` и не попадал
в баннер — новая зона по нему показывалась прочерком молча. Ветки разведены: устаревшие
зоны продолжают подсказывать (это вернее прочерка), но аккаунт при этом назван, а текст
баннера сменён на «may be missing or out of date» — утверждать одно из двух нельзя.
Причина отказа (`clip(errorText(e))` из `api/cfAutoBind.ts`) уехала в `title` баннера.

### Долг Фазы 1 (не блокирует, но записан)

- **Язык разъехался внутри одной фичи:** баннер английский (зеркалит соседний
  `CloudflareBindBanner`), `title` подсказки — русский (дословно из спеки).
- **Подсказка неотличима от факта для скринридера:** различие несут `fontStyle: italic` и
  `title`; текст ячейки в обоих случаях одинаков. В баннере причина тоже живёт только в
  `title`, но там есть хотя бы пунктирное подчёркивание как намёк.
- **Дом типа `UnreadCloudflareAccount`** — в `hooks/`, из-за чего
  `components/domains/CloudflareUnreadBanner.tsx` держит единственный в `src/components`
  импорт «вниз» в `hooks/`. Рантайм-цикла нет (импорт типовой), но рядом лежит прецедент:
  родственный `RowCfHint` живёт в `components/domains/types.ts`.
- **`clip`/`errorText` экспортированы из `api/cfAutoBind.ts`** — потребитель настоящий, но
  дом случайный: презентационный баннер теперь импортирует **значениями** модуль, который
  делает `apiPut` и `invalidateQueries`. Место двух чистых текстовых функций — `lib/`.
- **Разовый сбой сети оставляет баннер до конца визита:** `refetchOnWindowFocus` выключен,
  на открытой странице перезапрос никто не инициирует. Честнее прежнего молчания; если
  начнёт раздражать — лечится ссылкой «Retry» в самом баннере, а не возвратом к молчанию.
- **Цена открытия вкладки:** в десктопе страница на монтировании читает зоны каждого
  активного аккаунта. Плата за «показ без кликов»; кэш общий со страницей Cloudflare и
  прогоном привязки (`staleTime` 60с).

### Фаза 2 — что вышло по факту

Кнопка в шапке гоняет тот же `useCloudflareBind`, что и кнопка по выделенным: гейт «один
прогон за раз» (`MutationCache` / `CF_BIND_KEY`) не продублирован, обе кнопки гаснут от
одного `pending`, отчёт — существующий `CloudflareBindBanner`. Область — `domainsData`, то
есть весь ответ API **включая скрытые фильтром строки**: иначе итог синхрона зависел бы от
набранной строки поиска (`GET /domains` пагинации не имеет, фильтрация клиентская).

Главным содержанием фазы оказалась не сама кнопка, а **устранение трёх имён одного
действия**: подсказка строки звала «Нажми Синхронизировать», кнопка тулбара была подписана
«Match Cloudflare zones» и вдобавок появлялась только при выделении, а кнопка шапки стала бы
третьим именем. Сведено к одному глаголу с разной областью — «Синхронизировать с Cloudflare»
(весь список, видна всегда) и «Синхронизировать выделенные». Чтобы три поверхности не
разъехались снова, глагол и текст тултипа собраны из констант в `lib/cfZoneMatch.ts`
(`CF_SYNC_VERB`, `CF_SYNC_TITLE`, `CF_HINT_TITLE`) — переименование меняет все три разом
либо ни одной, есть тест на дрейф. Пропсы переименованы туда же (`onSyncCloudflare` /
`syncPending`), `syncPending` сделан обязательным: забытый проп оставлял бы кнопку бодрой на
весь прогон, и пользователь решил бы, что клик не сработал.

Побочно вскрылось и починено: `Btn` (`ui/Primitives`) молча выбрасывал `title`, хотя проп был
проложен и задокументирован в `OpenInDesktopProps`, а веб-ветка того же компонента тултип
рисовала. Из текста `nothingToDo` убрано слово «selected» — фраза общая на трёх вызывающих,
а синхрон из шапки выделения не спрашивает.

### Долг Фазы 2

- **Глагол обещает больше, чем действие делает.** «Синхронизировать» читается как
  двусторонняя сверка (создать недостающие зоны, снять протухшие привязки); делается одно —
  найти зоны по именам и проставить привязку там, где её нет. Границы названы только в
  `title`; прежнее «Match Cloudflare zones» описывало действие точнее, но разъезжалось с
  подсказкой в строке.
- **Две русские кнопки посреди английского UI** («File Import», «Bulk Add», «Assign Server»,
  «Provision»), и отчёт действия тоже английский. Долг Фазы 1 про язык этим стал заметнее:
  он вышел из `title` в два самых видных элемента экрана. Решается разом с языком всей
  вкладки, не здесь.
- **`title` на погасшей кнопке** браузеры трактуют по-разному; сочтено несущественным
  (вопрос «что будет, если нажать» задают до клика, а во время прогона ответ уже в подписи).
- **Тексты действия живут в `lib/cfZoneMatch.ts`** — модуле правила матчинга. Дом выбран как
  единственный общий предок трёх потребителей из разных папок, но UI-строки в модуле правил
  — компромисс, а не идеал.

### Фаза 3 — что вышло по факту

Таб-свитчер карточки убран, вкладка `ns` слита в Overview; `DomainDetailModal.tsx` ужался с
397 до 213 строк, состояние уехало вместе со своими кусками в `DomainCloudflareField.tsx`
(селект аккаунта + дорезолв зоны) и `DomainNsPanel.tsx` (NS + бейдж). Правила — чистыми
модулями с юнит-тестами: `lib/nsDelegation.ts` (лестница делегирования) и
`lib/registrarCaps.ts` (`registrarSupportsNsApi`, `registrarProviderKnown` — зеркалит
`make_service` десктопа **точно**, включая отсутствие `trim()`: `" hostiq "` десктоп не
знает, значит и фронт не должен).

**Лестница делегирования — семь причин `unknown`, а не одна**, потому что чинятся они семью
разными действиями; порядок проверок = порядок починки. Зелёное значит «делегирование
подтверждено Cloudflare»: незнакомый статус зоны даёт `pending`, а не `delegated` — ошибка в
эту сторону безопасна, в обратную нет.

**Главное, что вскрыло ревью.** Бейдж делегирования у Namecheap не мог быть ничем, кроме
серого UNKNOWN: `namecheap.domains.getList` nameservers не отдаёт вовсе (`nameservers:
vec![]`), а гейт всё равно оплачивал вызов чужого API. Корень — односторонность зеркала:
`registrarSupportsNsApi` списан с пути **записи** (`make_service`) и молча применён к пути
**чтения**; у провайдера это разные способности. Починено не заглушкой, а по существу:
`RegistrarService::get_nameservers` (был реализован у обоих провайдеров, но наружу не
выставлен — вызывающих ноль) выставлен новой Tauri-командой `registrar_get_nameservers`, и
карточка спрашивает NS **по одному домену** вместо листинга всего аккаунта.

По дороге выяснилось, что у Namecheap `get_nameservers` не работал и сам по себе: звал
`domains.getInfo`, а разбирал `DomainDNSGetListResult` — элемент из ответа
`domains.dns.getList`. Команда исправлена, разбор вынесен в чистую `parse_dns_get_list` с
Rust-тестами на реальную форму ответа.

Это же снесло причину `domain-not-at-registrar`: она возникала оттого, что домен не нашёлся
в **непагинированной** странице листинга (`namecheap.rs` шлёт `PageSize=100` без цикла,
`hostiq.rs` — без пагинации вовсе), и карточка на аккаунте в 250 доменов утверждала
конкретную, действенную и неверную вещь — «назначен не тот аккаунт». Вместо выдумки теперь
показывается правда регистратора: текст его отказа.

Добавлена седьмая причина — `zone-name-mismatch`. Nameservers Cloudflare выдаёт **одни на
весь аккаунт**, поэтому привязка к чужой зоне того же аккаунта сходилась по NS, статус её
`active` — и карточка показала бы зелёное «делегировано, Cloudflare подтвердил» про домен,
зоны которого в Cloudflare нет вовсе.

### Долг Фазы 3

- **Смена сетевой команды у Namecheap не проверена на живом аккаунте** (API-ключей у агентов
  нет). Первое, что смотреть при ручной приёмке: домен на Namecheap с активной зоной должен
  показать DELEGATED, а не UNKNOWN.
- **`IsUsingOurDNS="true"`** (домен на дефолтных NS Namecheap) намеренно отдаётся обычным
  списком — то есть это MISMATCH, а не «не знаем».
- **Аудита в новой команде чтения нет** — осознанно, как у соседних `registrar_get_domains`
  и `registrar_test_connection`: `audit_log` пишут действия, которые что-то меняют.
- **Карточка ходит в API регистратора на открытие** (теперь дёшево и поимённо, `staleTime`
  60с), плюс читает зоны аккаунта.
- **Автозапись без клика:** дорезолв пишет `cloudflare_zone_id` при открытии карточки — этого
  требует спека («чинит `skipped`-домены»), но пользователь такой мутации не инициировал.
- **Регресс, принятый осознанно:** на экране без вкладок отказ прошлой попытки виден сразу при
  переоткрытии карточки — раньше на Overview его не было. Смягчён адресованием по месту
  (алерт между полем и кнопкой); лечится признаком «эту попытку уже показывали», а не
  возвратом вкладок. В тесте это прямо названо регрессом.
- **`clip`/`errorText` по-прежнему живут в `api/cfAutoBind.ts`**, а импортируют их уже три
  презентационных компонента — долг Фазы 1 стал шире.
- **Сверка делегирования считается в модалке** и уезжает вниз пропсами; просится
  `useNsDelegation(domain, zone)` рядом с панелью — минус три пропса и минус повод править
  модалку при изменении правила.
- **`useZoneDetails`** остался без производственных вызывающих (осознанное решение плана №2 —
  см. `2026-08-11-domains-sroki-sortirovka-statistika.md`), фаза его не трогала.
