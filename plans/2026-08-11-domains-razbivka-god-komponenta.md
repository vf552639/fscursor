**Дата:** 2026-08-11

## Граница объёма

**В объёме:** только структура. Ни одного изменения в том, что видит и делает
пользователь. Разбивка, у которой «заодно» поехала вёрстка, не проверяема:
отличить намеренную правку от регрессии в диффе на 900 строк нельзя.

**Вне объёма — токены и тёмная тема.** `design-brief.md` описывает
**общеприложенческий** редизайн: единый слой CSS-переменных и тёмная тема для
всех экранов сразу. Сделать её только для Domains — значит создать визуальный
остров, несовместимый с остальным (светлым) приложением. Это отдельная
инициатива уровня всего фронта, а не задача вкладки. Инлайновые hex-цвета
переносим в новые файлы **как есть**, не «улучшая» по дороге.

## Edge cases

- **Состояние, общее для нескольких кусков** (выделение `sel`, фильтры,
  `focusDomainId`) — остаётся у оркестратора и уезжает пропсами. Не заводить
  контекст ради трёх потребителей и не дублировать состояние.
- **Гейт provision** (`useMutationState` по `PROVISION_DOMAIN_KEY`) — остаётся
  на уровне страницы: он про всю таблицу, а не про строку. Строка получает
  готовый флаг `isProvisioning` пропсом.
- **`onProvisionResult` / `onBulkProvisionResult`** — путь «результат → показ»
  переживает размонтирование страницы; при переносе его нельзя укоротить до
  локального стейта. Комментарии, объясняющие почему, переносить вместе с кодом.
- **Комментарии-объяснения** — в этом файле их много и они дорогие (каждый
  описывает конкретную поломку, которую предотвращает). Переносить вместе с
  кодом, которому они принадлежат; не выбрасывать и не «сжимать».
- **`AddDomainModal` экспортируется** из `Domains.tsx` — проверить grep'ом
  внешних потребителей перед переездом.

### Закрытый долг

- **(а)** развилка «страница жива → баннер, страницы нет → наверх» стала
  `hooks/useLiveOrAway.ts`; оба её потребителя (отказ массового прогона, итог
  привязки) зовут один хук.
- **(б)** кластер привязки собран в `hooks/useCloudflareBind.ts`
  (`{ notice, dismiss, pending, run }`).
- **(г)** `handleBulkAdd` больше не зовёт функцию, объявленную на 130 строк
  ниже: `BulkAddDialog` отдаёт созданные строки через `onCreated`.
- **M4** — гейт «один прогон привязки за раз» переехал в `MutationCache` под
  `CF_BIND_KEY` (тем же приёмом, что и признак массового provision). Уход со
  страницы посреди прогона и возврат больше не дают второго прохода. Есть
  тест, падающий на прежней реализации гейта. Это единственное намеренное
  изменение поведения.
- **План №2:** карточки среза — `interface StatCard` вместо кортежа через `as`;
  `Th` разъехался на `PlainTh` и `SortableTh` (обязательный `label`,
  несортируемый заголовок не таскает `sort`/`onSort`); `dateOf` — `switch` с
  проверкой `never`; `StatusBadge` стал `DomainStatusBadge` в
  `components/domains/`.

### Отклонённый долг

- **(в)** — четыре «доставки наверх» НЕ свёрнуты в один
  `onDetachedResult(kind, payload)`. Свёртка потребовала бы union-типа
  полезной нагрузки, и компилятор перестал бы требовать КАЖДЫЙ из четырёх
  обработчиков по отдельности — а именно это (см. JSDoc `onProvisionResult`)
  и делает потерю пароля невыразимой. Вдобавок после разбивки каждый проп
  зовётся ровно из одного места: два — из хуков, два — из тела страницы.
- **Императивная подсветка строки под курсором** (`e.currentTarget.style.
  background`) оставлена как есть. CSS `:hover` потребовал бы класса в
  `index.css`, где сейчас нет ни одного компонентного класса, — а такой же
  императивный ховер живёт ещё на шести страницах (`Servers`, `ServerDetail`,
  `Dashboard`, `Activity`, `Cloudflare`, `Notifications`). Перевести одну
  вкладку значит создать ровно тот визуальный остров, из-за которого из объёма
  исключены токены. Вдобавок сама починка (подсветка, уезжающая вверх при
  пересортировке) — изменение поведения, а его этот план разрешает только для
  M4. Долг остаётся и просится в общефронтовую работу по `design-brief.md`.
