# План: карточка домена — связи, регистратор и снятие дублей

**Дата:** 2026-08-17
**Связь с бизнесом:** карточка домена — главный экран диагностики («почему домен не
работает»). Сегодня она отвечает на этот вопрос дважды и по-разному, а третью связь
домена — регистратора — не показывает вовсе, из-за чего кнопка «Set NS at registrar»
гаснет без объяснимого способа это исправить.

## Что не так сегодня

Карточка (`DomainDetailModal`) склеена из двух блоков с РАЗНЫМИ источниками, и они
пересекаются восемью полями:

| Верхний блок (наша запись из provision) | Секция `Server state` (живое чтение по SSH) |
|---|---|
| `SSL` / `SSL expires` / `SSL issuer` | SSL → State / Expires / Issuer |
| `PHP` | Site → PHP |
| `Site user` | Site → Owner |
| `Site path` | Site → Path |
| `FTP user` | FTP access → Login |
| `DB name` / `DB user` | Site → Databases |

Путь сайта при этом печатается ТРИЖДЫ: `Site path` сверху, `home` в «Accounts on
server» и `Path` в Site.

Плюс два самостоятельных дефекта:

- `Registrar` печатает сырой `registrar_id` (`domain.registrar_id`), то есть число или
  прочерк. Назначить аккаунт регистратора в карточке негде, хотя панель NS внизу прямо
  требует это сделать: «Assign a registrar account to this domain first».
- Правый столбец верхнего блока целиком про сервер, левый — про домен. Колонки не
  означают ничего: это просто перенос строки на середине списка.

## Решение (утверждено в брейншторме 2026-08-17)

1. **Факт с сервера — главный.** Всё про сайт (SSL, PHP, путь, владелец, БД, FTP) живёт
   ТОЛЬКО в `Server state`. Наша запись из provision показывается там же и только
   тогда, когда расходится с фактом либо когда факта ещё нет.
2. **Верх карточки — цепочка связей.** Строка-сводка (status · срок · SSL) и три
   карточки: Registrar → Cloudflare → Server. Это и есть путь запроса к домену, и
   каждая связь получает своё место под селект и свой статус.
3. **Registrar становится живой связью:** имя аккаунта, метка провайдера и выпадашка
   назначения — по образцу существующего `DomainCloudflareField`.

### Целевая структура карточки

```

[active]  expires —  ·  SSL: Valid до 24.04.2041          ← сводка

  Site (на всю ширину)
─────────────────────────────────────────────────────

Nameservers …
```

## Acceptance criteria (что значит «готово»)

- [x] Ни одно поле про сайт (SSL, PHP, site path/user, FTP login, БД) не печатается на
      карточке дважды. Путь сайта — не более чем в двух местах (Site → Path и, если он
      ОТЛИЧАЕТСЯ, home FTP-аккаунта).
- [x] `Registrar` показывает имя аккаунта и метку провайдера, а не число; аккаунт
      назначается и меняется прямо в карточке; после назначения кнопка «Set NS at
      registrar» ведёт себя ровно так же, как если бы аккаунт назначили в списке доменов.
- [x] Бейдж SSL в сводке и состояние SSL в `Server state` считаются ОДНОЙ функцией
      (`sslState`) и не могут разойтись. Непроверенный домен получает серый
      «Not checked», а не зелёный.
- [x] Расхождение нашей записи с фактом видно строкой «при развёртывании: X» под
      значением; при совпадении строки нет вовсе.
- [x] Домен, который ни разу не проверяли на сервере, не показывает решётку прочерков:
      секция говорит «Never checked» и предлагает кнопку, а известные из provision
      значения показаны приглушённо с подписью «из provision, на сервере не проверено».
- [x] Существующие тесты карточки (`DomainDetailModal.*.test.tsx`,
      `DomainServerFacts.test.tsx`) обновлены и проходят; логика расхождения покрыта
      своим тестом.

## Edge cases (продумать заранее)

- **Домена без сервера** (`server_id === null`): карточка Server говорит «не назначен»,
  FTP Host в `Server state` остаётся прочерком (как сегодня).
- **Аккаунт регистратора удалён, а `registrar_id` в домене остался.** Селект НЕ должен
  молча показывать «не назначен» — это обещание, что связи нет, тогда как в БД она есть.
  Показываем `id` и подпись «аккаунт не найден». (У `DomainCloudflareField` этот случай
  сегодня не разобран — здесь его надо разобрать, но чужой компонент не трогаем.)
- **Список аккаунтов ещё грузится** (`useRegistrarAccounts().isPending`): селект
  disabled, подпись «загрузка», а не «не назначен».
- **Веб (не Tauri).** Назначение регистратора — это метаданные (`PUT /domains/{id}`),
  и в вебе оно работает, ровно как работает селект Cloudflare. Принцип 3 не нарушен:
  выполнение (пуш NS через API регистратора) как было, так и остаётся десктопным.
- **Провайдер без API** (ручной ярлык). Карточка Registrar про это НЕ говорит —
  ответственность за «умеет ли писать NS» остаётся у панели NS внизу
  (`registrarSupportsNsApi`), и второй такой ответ на одном экране означал бы два
  источника правды. Сознательно вне объёма.
- **Формат PHP расходится не по сути:** provision пишет `8.1`, FastPanel отдаёт `81`.
  Наивное сравнение строк даст ложное расхождение на каждом домене. Сравнение
  нормализуем (см. фазу 1).
- **SSL expires:** `facts.ssl.expires_at` — полный datetime, `domain.ssl_expires_at` —
  тоже. Сравниваем по календарной дате, а не по строке, иначе разница в секундах
  выдаётся за расхождение.
- **`db_user` соответствия на сервере не имеет вовсе** (`facts.databases` — только
  имена). Он всегда «наша запись», а не расхождение.
- **Много FTP-аккаунтов на сервере:** список остаётся как есть, дедуп пути — только
  против пути сайта.
- **Zero-knowledge:** новых секретов план не вводит. `FtpPassword` и `RevealSecret`
  не трогаем; в карточке Registrar никаких ключей и секретов не показываем — только
  имя аккаунта и провайдер.
- **Двойное изменение селекта:** `disabled={update.isPending}`, как у Cloudflare.

## Фазы

### Фаза 1 — правило расхождения и общий бейдж SSL  `[x]`

Чистая логика, до всякой вёрстки. Пишется тестами вперёд.

**Новый файл `frontend/src/lib/domainDrift.ts`.**

Одна функция на поле, три исхода — потому что вопросов тут ровно три, и «нет данных»
не то же самое, что «совпало»:

```ts
export type FieldSource =
  | { kind: "agree" }                              // факт есть, наша запись с ним совпала
  | { kind: "drift"; recorded: string }            // факт есть, наша запись другая
  | { kind: "recorded-only"; recorded: string };   // факта нет, есть только наша запись
```

- `agree` → в UI ничего не дорисовывается.
- `drift` → серая строка «при развёртывании: {recorded}».
- `recorded-only` → значением поля становится `recorded`, приглушённым, с подписью
  «из provision, на сервере не проверено».

Правила сравнения (каждое — со своим тестом):

| Поле | Наша запись | Факт | Как сравниваем |
|---|---|---|---|
| FTP login | `domain.ftp_user` | `facts.ftp_accounts[0].login` | trim, регистр учитываем |
| Site path | `domain.site_path` | `facts.site.site_path` | trim, хвостовой `/` не в счёт |
| Site owner | `domain.site_user` | `facts.site.site_user` | trim |
| PHP | `domain.php_version` | `facts.php_version ?? facts.site.php_version` | только цифры: `8.1` ≡ `81` |
| SSL expires | `domain.ssl_expires_at` | `facts.ssl.expires_at` | по календарной дате |
| SSL issuer | `domain.ssl_issuer` | `facts.ssl.issuer` | trim |
| DB name | `domain.db_name` | `facts.databases` | расхождение, если имени нет в списке |
| DB user | `domain.db_user` | — | всегда `recorded-only` |

Пустая строка, `null` и `undefined` уравнены — ровно как это уже делает `Field` в
`DomainDetailModal`.

**Вынос `SSL_BADGE`.** Сегодня карта ярлыков и цветов SSL живёт внутри
`DomainServerFacts.tsx`. Её нужны ДВА читателя (сводка и секция), а два экрана,
считающие состояние сервера по своей копии правила, в этом проекте уже разъезжались
(принцип 6). Переносим `SSL_BADGE` в `frontend/src/lib/domainFacts.ts`, рядом с
`sslState`, который её и питает.

Файлы: `frontend/src/lib/domainDrift.ts` (новый),
`frontend/src/lib/domainDrift.test.ts` (новый),
`frontend/src/lib/domainFacts.ts` (правка), `DomainServerFacts.tsx` (импорт).

## Итог

> **Приписка 2026-08-20: решение «сервер на карточке read-only» отменено.**
>
> Оно опиралось на неверный факт. Подпись «A domain gets its server when it is deployed»
> утверждала, что связку ставит развёртывание, — но provision `server_id` **не ставит,
> а читает**, и без него падает с `domain has no server_id`
> ([provision.rs:1071](../desktop/src-tauri/src/commands/provision.rs#L1071)). То есть
> связка обязана существовать ДО развёртывания, и read-only поле не охраняло инвариант,
> а блокировало нормальный путь: назначить сервер можно было только в мастере «Add
> Domain», массовом «Assign Server» и full-setup. Инвариант к тому же уже нарушался —
> `bulk-assign-server` писал `server_id` без единой проверки.
>
> Заменено на `DomainServerField` (селект по образцу соседнего `DomainRegistrarField`)
> в плане [2026-08-20](2026-08-20-privyazka-domena-k-serveru.md), фаза 2. Там же
> закрыто то, чего этому решению не хватало для честности: смена `server_id` обнуляет
> снимок `fp_facts` старой машины (иначе вкладка Server показывала бы FTP-логин прежнего
> сервера рядом с IP нового), а выбор проверяется по A-записи Cloudflare — подсказкой,
> не запретом.
>
> Долг «`DomainCloudflareField` молча падает в „— No Cloudflare account —“», записанный
> ниже, после той работы стал очевиднее: правило «удерживать значение и назвать not
> found» теперь в двух полях ряда из трёх.


- Реализован целиком: **да** — фазы 1–5, ветка `feat/domain-card-links-registrar`,
  14 коммитов. Сюита 1122/99, `tsc --noEmit` чист, `npm run build` проходит. Чисто
  фронт: `git diff master...HEAD -- backend/ desktop/ nginx/` пуст.
- Что осталось: живая приёмка человеком (6 пунктов ниже) и долг (9 пунктов).

### Как исполнялось

Каждая фаза — отдельный агент, после каждой два ревью: соответствие спеке, затем
качество кода. Все замечания закрыты, спорные — с обоснованием. Финальное ревью ветки
проверило замок **мутациями**: девять правил ветки сломаны в копиях и прогнаны против
сюиты — убиты все девять (наша запись, заслоняющая факт FTP; схлопывание
`recorded-only` в `agree`; `recorded-only`, нарисованный как факт; зелёный `unchecked`;
`sslState`, возвращающий `valid` на протухшем снимке; удалённый регистратор, выданный
за «не назначен»; `home`, печатаемый всегда; PUT со старым `registrar_id`; второй
источник правды для бейджа SSL).

### Что ревью вскрыло сверх плана

- **Пустой список фактов давал бы «при развёртывании: X» на КАЖДОМ домене.** Провод не
  отличает «баз нет» от «не прочитали»: `list_site_databases` схлопывает в `Ok(vec![])`
  и успешное «пусто», и падение обеих команд (`fastpanel_facts.rs:453-471`), причём
  `databases_from_json` различие держит явно, а `Vec<String>` его теряет. Та же
  неоднозначность у FTP была решена в обратную сторону. Свели к одному вердикту
  (`compareInList`): пустой список — незнание. Развести по-настоящему можно только в Rust.
- **`digits()` давал ложное расхождение на patch-версии PHP:** `7.4` против `7.4.33` →
  `"74"` ≠ `"7433"`, а `coerce_php_version` три компонента прямо допускает
  (`fastpanel.rs:1082`). Заменено на `phpKey()` — первые два числа.
- **Правило FTP-логина стояло на несуществующем основании.** «Первый аккаунт = основной»
  производителем не подкреплено: `filter_ftp_by_domain` сохраняет порядок вывода CLI и
  ничего не размечает. Перешли на вхождение в список — список и так сужен по `home_dir`
  домена.
- **Шапка модалки утверждала, что паролей на карточке нет.** Фраза пережила снятие
  двухколоночного блока, где «здесь» значило «в этом блоке», и в шапке файла стала
  описанием всего экрана — при том что `FtpPassword` с `RevealSecret` на карточке есть.
- **`ssl_status` пропал бы молча.** План предписывал удалить поле `SSL`, но его премиса
  («переходит под `Server state`») для этого поля не работает: `ssl_expires_at` и
  `ssl_issuer` получили дом через `domainDrift`, а у `ssl_status` дома нет — его пара на
  сервере это `sslState`, другая величина. Список при этом красит домен по `ssl_status`
  до сих пор (`DomainRow.tsx:182-183`), то есть человек кликал бы красную строку выяснить
  причину, а карточка молчала. Хуже: write-back провижининга при провале SSL **гасит
  `last_provision_error` в `null`** (`provision.rs`, `domain_write_back_body`) и текст
  certbot не сохраняет вовсе — от провала не оставалось ни бейджа, ни строки ошибки,
  ни следа. Вернули строкой `SSL at provision:` рядом с `NS`, только при `error`/`pending`.
- **Ряд плашек давал бы карточке горизонтальный скролл.** На плашку приходится ~200px
  (760 − 2×28 паддинга = 704, `(704 − 24)/3` − 24 − 2), а `<select>` тянется по самой
  широкой опции: одна заглушка «— No Cloudflare account —» это ~190px. `Modal` ставит
  `overflowY: auto`, из-за чего `overflow-x` вычисляется в `auto`. Та же дыра нашлась
  этажом ниже: сетка `Server state` осталась `1fr 1fr` (это `minmax(auto, 1fr)`).

### Отступления от буквы плана (осознанные)

1. **У плашек нет отдельного заголовка** — `DomainRegistrarField` и `DomainCloudflareField`
   уже печатают `Registrar:` / `Cloudflare:` первым словом, и заголовок над ними напечатал
   бы одно слово дважды в каждой плашке. Имя плашки даёт сам жирный ярлык + `role="group"`.
2. **Подпись «из provision, на сервере не проверено» под `noSnapshot` даётся ОДИН раз
   легендой**, а не под каждым из восьми полей. Восемь дословно одинаковых строк на самом
   частом экране продукта (только что развёрнутый домен) — это против принципа 2;
   приглушённый цвет связывает значения с легендой. В смешанном случае (снимок есть, факта
   у поля нет) приписка печатается по-прежнему — там она единственный носитель знания.
3. **`DomainCloudflareField` тронут**, хотя план запрещал: три свойства CSS
   (`maxWidth: 100%`, два `overflowWrap: anywhere`). Логики, состояний, текстов и
   `ZoneNote` не касались. Причина — фаза 3 сама поставила компонент в контейнер втрое
   уже прежнего; известный долг компонента остался нетронутым.
4. **`samePath` вынесена наружу из `domainDrift.ts`** — план требовал, чтобы дедуп `home`
   считался ТОЙ ЖЕ нормализацией, а до этого правило жило анонимной лямбдой.
5. **Перечень «Accounts on server» гасится целиком**, когда не добавляет ничего (единственный
   аккаунт совпадает с показанным `Login`, `home` привычный), — вместо фильтрации основного
   логина из списка. Список, из которого молча изъят элемент, врёт своему заголовку.

### Долг (не закрыто, по убыванию цены)

1. **Колонку SSL в списке доменов перевести на `sslState`.** Сегодня список считает по
   `ssl_status`, карточка — по снимку; строка `SSL at provision:` это лечит симптом, а не
   причину. Невозможно без правки `DomainUI` (`domains/types.ts:12-27` не несёт ни
   `fp_facts`, ни `fp_facts_at`) — отдельная функция со своим планом.
2. **Протухший снимок звучит двумя голосами:** бейдж уходит в `Not checked`, а
   `Expires`/`Issuer`/`Path`/`Owner`/`PHP`/`Databases` под ним печатаются уверенным
   цветом. Логически это согласовано (`sslState` документирует асимметрию: выводы о СРОКЕ
   протухание переживают, о НАЛИЧИИ — нет), и шапка секции честно печатает `stale`, но
   рядом стоят «не проверяли» и уверенное значение. Лечение — легенда над сеткой по
   образцу `noSnapshot`; приглушённый цвет занимать нельзя, он уже значит `recorded-only`.
3. **`DomainCloudflareField` ведёт себя хуже соседа на двух состояниях:** сохранённый, но
   не найденный аккаунт молча падает в «— No Cloudflare account —» (рисует «связи нет»
   поверх связи, которая в БД есть), и селект не выключается на непрочитанном списке.
   Расхождение задокументировано в `DomainRegistrarField.tsx:49-58`. Снимается переносом
   нового правила в соседа — самый очевидный следующий шаг.
4. **Сводка и секция подают в `sslState` разные входы:** секция сначала гасит факты по
   `fp_facts_at`, сводка передаёт `domain.fp_facts?.ssl` напрямую. Сегодня результаты
   совпадают (`sslState` сама возвращает `unchecked` при `!factsAt`), но не по построению.
   Лечение — считать состояние один раз в модалке и раздать вниз.
5. `phpVersionSource` и печать PHP расходятся на пробельном `facts.php_version`: правило
   возьмёт `site.php_version`, экран напечатает пробелы.
6. `id="cf-account"` статический и без `aria-describedby` на свою ноту (у регистратора
   сделано). Правильная связь требует обернуть `ZoneNote` в узел с `id` — правка структуры.
7. Четыре копии цветовых констант (`NOTE_TEXT`/`WARN_TEXT`/`ERROR_TEXT`/`MUTED`) в четырёх
   файлах — объём будущей миграции на токены `design-brief.md`.
8. `Last error` в карточке теперь обрезается `clip()` (в master печатался целиком); полный
   текст остался в строке списка.
9. **Двуязычие секции `Server state`:** английская проза (`Never checked`, `not set`,
   `not read`) рядом с русскими строками (`Проверить на сервере`, легенда,
   `при развёртывании: X`). Закрывается только словарём интерфейса.

### Живая приёмка человеком (агенты доступа к Cloudflare/Hostiq/FastPanel не имели)

**jsdom вёрстку не считает вовсе, поэтому НИ ОДИН тест ветки не проверяет геометрию.**

1. **Ряд связей на 760px.** Карточка домена с длинным именем аккаунта Cloudflare И
   регистратора, длинным именем сервера, IPv6. Смотреть: не наезжают ли селекты на
   соседнюю плашку, нет ли у модалки горизонтальной полосы.
2. **`Server state` на настоящем снимке.** Домен, у которого `home` FTP-аккаунта
   отличается от пути сайта (длинный путь); настоящий `facts.ssl.error`; настоящий
   `fp_check_error` длиной в трассировку.
3. **Главное — ложные расхождения.** «Проверить на сервере» на ЗДОРОВОМ домене, где
   provision и FastPanel согласны. Ожидание: строк «при развёртывании: …» **не должно быть
   ни одной**. Если высыпались под каждым полем — нормализация (`8.1` ≡ `81`, хвостовой
   слэш, календарная дата вместо секунд) не поймала живой формат, и подпись обесценится
   с третьего домена.
4. **Назначение регистратора из карточки.** Выбрать аккаунт в плашке Registrar и, не
   закрывая карточку, убедиться, что кнопка «Set NS at registrar» внизу стала активной.
   Проводка проверена чтением кода, живого клика не было.
5. **Домен с `registrar_id` на удалённый аккаунт** — должно быть `#N · account not found`,
   а не пустой селект. Воспроизводится только удалением учётки в настоящей БД.
6. **Отказ чтения списка аккаунтов** (протухший токен) — под селектом строка
   `Registrar accounts could not be read: …`, селект выключен.
