## Правила

1. **Один план = одна функция.** Если план для функции уже есть — работаем с ним, а не создаём новый.
2. **Имя файла:** `YYYY-MM-DD-название-функции.md` (например, `2026-08-05-billing-phase3.md`).
3. **Каждый план делится на фазы.** У каждой фазы статус `[ ]` (не сделано) или `[x]` (сделано).
4. **В конце плана — итоговый блок:** реализован целиком или нет, что осталось.
5. **Актуализация обязательна:** любой агент, работающий с планом, отмечает сделанные фазы
   и дописывает, что сделал, после каждой сессии.

## Цикл работы с планом

1. Claude пишет первичный план в `plans/YYYY-MM-DD-название.md`.
2. Ты копируешь ссылку на файл, открываешь **новый чат**.
3. В новом чате просишь глубокую критику плана через параллельных субагентов
   (техническая реализуемость, соответствие бизнес-целям, UX).
4. Возвращаешься к плану и обновляешь его с учётом критики.
5. Только после этого — реализация (по триггер-фразе «Реализуй фазу N по плану»).

См. шаблон одного плана: `_TEMPLATE-плана.md`.
