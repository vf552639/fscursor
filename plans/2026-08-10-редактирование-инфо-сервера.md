# План: короткое имя OS + редактирование полей сервера в карточке Server Information

## Context (зачем)

Во вкладке Server на странице деталей блок **Server Information** показывал OS автоопределённой
строкой из `/etc/os-release` вида «Ubuntu 20.04.6 LTS» (поле `os_pretty`, снимается по SSH).
Нужно короткое имя семейства («Ubuntu») — и на детали, и в списке серверов.

Второе: редактировать можно было только **имя** (карандаш у заголовка страницы) и **провайдера**
(кнопка «✎ Provider» в шапке карточки). Четыре поля — **Name, IP, Provider, OS** — должны
править́ся прямо из строк карточки по единому паттерну «карандаш в строке → модалка».

Решения, согласованные с пользователем:
- **OS редактируемое** через тот же закрытый список из 5 значений, что и в форме Add Server;
  ручной выбор **перекрывает** автоопределённое значение; везде показываем короткое имя.
- **Карандаш в строке** только в десктоп-сборке (`isTauri()`) — правка это мутация, а веб
  read-only.

Фича задумывалась чисто фронтендовой: бэкенд (`ServerUpdate`, `server_service.update`) уже
принимает `name`, `ip_address`, `os`, `provider` через `PUT /servers/{id}` с `exclude_unset`;
Rust `update_command` уже покрывает пять значений `OS_OPTIONS`. Бэкенд и десктоп не тронуты.

## Фазы

### [x] Фаза 1. Общий модуль короткого имени ОС

`frontend/src/lib/osName.ts`:
- `OS_OPTIONS` переехала сюда из `Servers.tsx` вместе с JSDoc (контракт с Rust
  `update_command`), значения не менялись;
- `osShortName(label)` — любую строку ОС в каноничное короткое имя;
- `serverOsName(s)` — принимает сущность, решает приоритет «ручной `os` перекрывает
  автоопределённый `os_pretty`». Появилась **по требованию ревью**: правило было объявлено
  контрактом модуля, а жило в двух копиях на двух экранах — ровно та ошибка, ради которой
  модуль и заводился (ср. `serverStatus.ts`).

Подключено в двух точках показа: `ServerDetail.tsx` (`osLabel`) и `Servers.tsx` (поле `os`
в маппинге, питает бейдж грид-карточки и ячейку таблицы).

**Что нашло ревью в этой фазе.** Набор распознаваемых семейств был уже, чем у Rust-матчера:
`Red Hat Enterprise Linux 9.3` давало обрубок «Red», а `Cent OS 7` (форма с пробелом, под
которую в Rust держат отдельный тест) — «Cent». Иголки расширены и укорочены до `cent`/`alma`,
добавлены `rhel`/`red hat`/`fedora`. Порядок иголок стал нагруженным (производный дистрибутив
обязан бить апстрим: `Rocky Linux 9.3 (RHEL 9 compatible)` — это Rocky, а не Red Hat) и закреплён
комментарием и тестом.

### [x] Фаза 2. `InfoRow` учится показывать карандаш

`frontend/src/components/ui/Primitives.tsx`: необязательные `onEdit?: () => void` и
`editLabel?: string`. Карандаш рисуется через существующий `RowActions` — единственный примитив,
который сам ставит глифу `title`/`aria-label`. Без `onEdit` разметка идентична прежней
(проверено ревьюером сравнением `innerHTML` старой и новой версий).

`editLabel` нужен не для гипотетики: скринридер читает «OS» и «IP» по буквам, поэтому строкам
передаются `"operating system"` и `"IP address"`.

### [x] Фаза 3. Редактируемые строки + две новые модалки

`frontend/src/pages/ServerDetail.tsx`:
- строки Name / IP / Provider / OS несут `onEdit` (только под `isTauri()`), остальные
  read-only; ключ в `.map` — подпись строки, а не индекс;
- Name и Provider переиспользуют существующие модалки Rename и Hosting Provider;
- новые модалки IP и OS по паттерну файла: `show*Modal` + `open*Modal` (префилл из сущности) +
  `handleSave*`, **ровно одно поле** в теле мутации, ошибка в своём `*Err`, а не в общем
  `updateServer.isError`;
- кнопка «✎ Provider» из шапки карточки убрана; в вебе там остаётся `DesktopOnlyNote`.

### [x] Фаза 4. Валидация адреса вынесена в `lib/` (появилась по ходу ревью)

`frontend/src/lib/ipInput.ts` — `ipError(value, opts?)` по образцу `providerInput`/
`fastpanelInput`. `Servers.tsx` зовёт `ipError(ip)`, `ServerDetail.tsx` —
`ipError(ip, { ipv6: true })`: разница правил стала именованным параметром, а не двумя
регулярками, которые сверяют глазами.

## Что нашло ревью (главное)

Три из восьми коммитов — правки ревью, и два дефекта были настоящими, не косметическими.

**1. Проверка адреса пропускала почти что угодно.** Первая версия:
`/^(?:[0-9]{1,3}\.){3}[0-9]{1,3}$|:/` — правая ветка альтернации не заякорена, то есть «в строке
есть двоеточие». Проходили `1.2.3.4:22` (самая частая форма записи адреса в заметках про SSH),
`http://example.com`, `не адрес: тут`. Бэкенд формат `ip_address` **не проверяет вовсе**, так что
значение уехало бы в колонку, оттуда в `host` SSH-подключения — отказ без внятной причины.
Заменено разбором IPv6 (не регуляркой: на все формы она нечитаема). Ревьюер проверил разбор
дифференциально против `net.isIP` из Node — 48 краевых случаев и фаззинг на 600 000 входов,
0 расхождений, кроме четырёх намеренных (голое `::`, зона `%eth0`, два следствия `trim()`).

**2. Модалка OS противоречила строке, из которой её открыли.** Для Fedora-сервера строка карточки
честно показывала «Fedora», а открытый из неё селект — «Debian» (первый пункт закрытого списка).
Цена одного случайного Save: `provision.rs:1649` читает **именно колонку `os`**, `update_command`
даёт `apt` на Fedora, и получасовая установка FastPanel ломается на первом шаге; откатить нечем,
потому что `os` теперь перекрывает `os_pretty` и бейдж тоже начнёт врать. Закрыто нерабочим
пунктом-заглушкой («Fedora — не в списке») и мёртвой кнопкой Save, пока не выбрано осознанно.

**3. Половина фичи не была покрыта.** Финальное ревью вернуло показ в списке серверов к прежнему
выражению — **556 тестов остались зелёными**. У `serverOsName`, чей JSDoc называет её
«единственным местом, где решается приоритет», не было ни одного прямого юнит-теста. Закрыто.

### Осталось (долг, за рамками этого плана)

1. **IPv6-сервер не может подключить FastPanel.** Адрес с двоеточием теперь ввести можно, а
   `fastpanelUrlError` (`lib/fastpanelInput.ts`) и парные ему `_HOST_PORT_RE` в
   `backend/app/core/validators.py` и `host_port_regex()` в десктопе bracketed-IPv6 не принимают.
   В этой ветке закрыт только симптом (форма подключения не префиллит заведомо невалидный URL);
   настоящее лечение — расширить три регулярки одним заходом, а это бэкенд и Rust.
2. **Массовый импорт по-прежнему не принимает колонку `os`** — теперь это не тупик (OS правится
   из карточки), но каждому импортированному серверу ОС приходится проставлять руками.
3. **Два карандаша на одно действие.** Переименование доступно и у заголовка страницы
   («Rename server»), и из строки Name («Edit Name») — план прямо просил сохранить первый.
   Для скринридера это два разных действия на одно и то же. Решение — за пользователем.
4. **`update_command` — `else`-fallback, а не whitelist** (наследство, см. предыдущий план):
   нераспознанная ОС молча получает `apt`.
